# Статус приёмки

Дата: 2026-09-09. Groq снова доступен после временного HTTP 403. Полный прогон с автоматическим поиском, 12 ролями до реализации и 12 экспериментами завершён. Генератор другого сценария проверен тремя реальными вызовами Groq. Мастер-промпт целиком ещё не принят: технические фикстуры не заменяют реальные бизнес-данные, решение и приёмку MVP человеком.

## Проверено

- 34 unit-теста Python в Docker: расчёты, схемы, доказательность, зависимости, политика провайдеров, изолированный JavaScript и извлечение ссылок только из результатов поискового инструмента. Контрольный расчёт проверяет замену оценочной ручной доработки замеренной без двойного учёта; базовый прогноз использует те же параметры. Тесты политики используют mocks для доказательства отсутствия сетевого вызова; это не доказательство доступности Groq.
- TypeScript noEmit и production build Next.js. После уточнения подписей Groq и демоданных повторная Docker-сборка Web прошла с проверкой TypeScript.
- Миграции 001–007 на PostgreSQL 15. API, Worker, Runner, Rules, egress, PostgreSQL, MinIO и production Web запущены через Compose. Постоянные данные находятся в pgdata, objects и runner_state.
- Groq GET /models, реальная классификация и структурирование карточки: openai/gpt-oss-20b. Распознавание русской речи: whisper-large-v3-turbo. Тариф аккаунта не выводится из ответа /models; автоматической покупки/смены тарифа нет.
- Русский WAV 11,04 секунды (синтетический голос для технического теста) распознан: «Хочу создать сервис для классификации обращений поддержки Он должен различать проблемы оплаты и доступа к личному кабинету». Оригинал и исходный текст доступны отдельными S3-артефактами; исправление создаёт IdeaVersion.
- Восемь API smoke-проверок: авторизация, сохранение карточки, версия, конкурентный конфликт 409, изоляция Owner/Reviewer 404, запрет анонимного чтения 401, dataset, идемпотентный запуск.
- Полный Groq ResearchRun 46cc348e-91b3-4161-9895-4fcedadadb6d завершён: пять workflow-шагов, 13 ИИ-вызовов, два варианта × две задачи × три повтора = 12 сохранённых наблюдений, реальные обращения к Rules, расчёт, критическая оценка и отчёт.

Новый запуск c1cab129-ca54-4862-8383-f52d31573b53 завершился с одним ИИ-вызовом исследования; независимые эксперименты переиспользованы без новых вызовов. После наблюдения monthly_volume очередь metric_jobs создала новую версию расчёта и отчёта.
- Отдельный lifecycle-тест: исходное аудио возвращается байт в байт, исправленная версия сохраняется, команды pause/resume/cancel идемпотентны, отменённый запуск не возобновляется; archive/activate; удаление карточки возвращает 404, deletion_jobs завершается, оба S3-объекта действительно отсутствуют. Тестовая идея удалена самим тестом.
- Браузер: реальный вход Reviewer, сохранённые идеи, настройки интеграций, итоговый Groq-отчёт, расчёт и история версий. Ранее проверены мобильная ширина 390 px без общей горизонтальной прокрутки и открытие внутренних документов. Production-интерфейс доступен на http://localhost:3000.

Демонстрационный dataset содержит синтетический baseline 30/40 секунд и две тестовые задачи, поэтому n=2, а не 6 повторений. Время вызовов измерено реально, но разница с этим baseline не доказывает бизнес-экономию. Рекомендация — «Недостаточно данных»: доступно только три из пяти запрошенных источников, нет первичных измеренных бизнес-данных. В UI есть явная пометка о демоданных. Принятие MVP на таком основании не выполнялось.

## Воспроизведение

Unit: docker compose exec -T api python -m unittest discover -s tests -p test_*.py

Интеграционные скрипты находятся в backend/tests/integration_smoke.py, integration_followup.py и integration_lifecycle.py. Они создают явно обозначенные данные в пространстве Reviewer и делают реальные вызовы Groq в пределах квоты. Followup получает TEST_IDEA_ID завершённого smoke. Lifecycle использует сохранённые в этой рабочей БД аудио и dataset как исходные фикстуры; для чистой установки сначала нужны эти материалы. Скрипты не входят в автоматический unittest discover.

## Открытая приёмка мастер-промпта

- Все 13 функций реализованы с сохранением отдельных StepDefinition/StepResult в agent_results. 12 функций до реализации проверены полным живым прогоном; шесть исследовательских функций используют один валидированный ответ с отдельными полями. implementation_agent и полный путь mvp_jobs → версия → реальный ввод → сохранение → API приёмки проверены технической фикстурой в отдельной БД. Решение и приёмка продуктового MVP человеком остаются открытыми. Старые прогоны автоматически новыми результатами не дополняются.
- MVP генерируется по идее и критериям как типизированная форма → ИИ → чистый JavaScript → результат. Поддерживаются текстовые/структурированные операции, без произвольных библиотек, файлов и публикаций. Реальные вызовы для извлечения заказа и расчёта итога проверены ниже. Нужны измеренные данные, рекомендация «Развивать», решение и приёмка пользователя для полного продуктового сценария. Генерируемые ai_fixture проверяют transform, а не качество модели.
- После SIGKILL Worker восстановление перед расчётом проверено в копии БД; аварийное завершение Worker на экспериментальном этапе тоже завершилось восстановлением без дублирования наблюдений. Попадание SIGKILL точно внутрь незавершённого внешнего ИИ-вызова не подтверждено: к следующему опросу запрос уже завершился. Сохранность завершённого результата после SIGKILL Runner проверена; неизвестный исход прерванного вызова блокирует автоматический повтор.
- Полный производственный overhead и реальные ручные операции пока не измерены. Таймер, привязка к версии dataset и пересчёт реализованы и проверены техническими демозамерами. Незамеренные этапы остаются допущениями. Баллы рубрики отражают полноту артефактов, а не доказанный спрос.
- Репозиторий исходников: [NikitaUwu/TestFarm](https://github.com/NikitaUwu/TestFarm). Внешнее развёртывание приложения не выполнено. Реальный микрофон пользователя, отказ в разрешении и длительная запись требуют отдельного браузерного прогона.

Подтверждение интеграции Groq не означает закрытие этих требований §48.
