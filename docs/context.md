# Контекст продукта

Актуально для исходников на 22 сентября 2026 года. [Путеводитель по документации](README.md) отделяет текущую реализацию от исторических материалов. Первоначальный `МастерПромпт.md` упоминается в `AGENTS.md`, но отсутствует в текущем checkout; доступные источники решений — [отчёт v1.3](target-report-v1.3.md), `AGENTS.md` и код.

Продуктовая ферма помогает владельцу идеи быстро получить основания для решения: развивать гипотезу, проверить её дополнительно или остановить. Пользователь фермы отличается от аудитории исследуемой идеи. Исследование выполняется в основном автоматически; человек вводит идею, при желании исправляет её и принимает решение по отчёту.

## Основной сценарий

1. Пользователь регистрируется или входит по логину либо почте и паролю.
2. Вводит идею текстом, записью с микрофона или аудиофайлом. Результат распознавания можно исправить в текстовом поле.
3. Выбирает приоритет и запускает исследование. Идея и её версия сохраняются в Neon, задача попадает в очередь.
4. Workflow анализирует аудиторию, ищет открытые источники, формулирует гипотезы, предлагает два варианта, выполняет ограниченные прогоны и вызывает численный расчёт.
5. Отдельная модель критикует доказательства и расчёт. Отчёт показывает рекомендацию, цитаты, допущения и ограничения.
6. Пользователь решает: создать MVP, отправить идею на доработку или остановить её. Запуск MVP по решению пользователя может быть отмечен как `override`, если рекомендация не была положительной; это текущее поведение API, а не подтверждение качества идеи.
7. MVP выполняет один сценарий по декларативной спецификации. В отчёте есть дополнительные интерактивные блоки прогноза и пилотных наблюдений; их ограничения описаны в [методике](calculation.md).

## Словарь

| Термин | Значение |
| --- | --- |
| `Idea` | Рабочая карточка владельца с названием, текстом, приоритетом и стадией |
| `IdeaVersion` | Сохранённый снимок содержательного входа; старые запуски помечаются `stale` |
| `ResearchRun` | Исследование определённой версии идеи и снимка конфигурации |
| `Job` | Элемент очереди для исследования или сборки MVP |
| `Step` | Сохранённый результат этапа Workflow |
| `EvidenceSource` | Ссылка и реально возвращённый поисковый фрагмент, без чтения полной страницы |
| `Trial` | Выполнение варианта на конкретной задаче и повторении |
| `CalculationRun` | Детерминированный расчёт по сохранённым данным прогона |
| `Report` | Снимок выводов по одному ResearchRun |
| `MvpSpec` | Разрешённые поля ввода/вывода, промпт и флаг правил; исполняемого кода нет |

## Границы

В одном Vercel-проекте работают веб-интерфейс, API, Workflow, Python Function и HTTP-компонент Rules. Neon хранит бизнес-данные, Private Blob — аудио и JSON-артефакты, RouterAI — внешний шлюз LLM, распознавания речи и поиска через Exa. Командных пространств, биллинга пользователей, произвольного запуска сгенерированного кода и переноса прежней базы в текущем объёме нет. Исторические данные не удалялись.

Синтетические персоны и примеры — материал для проверки цепочки, не интервью и не доказательство спроса. Оценка часов или рублей по введённым предположениям — прогноз. Только фактически сохранённые сопоставимые измерения могут считаться измеренным эффектом. [Статус и пробелы](verification.md) фиксируют, что подтверждено исходниками, а что требует отдельной проверки.
