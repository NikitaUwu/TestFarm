# Исследование и численный расчёт

Этот документ различает возвращённые внешние фрагменты, синтетические примеры, измерения прогонов и прогнозы. Настраиваемые числа берутся из `web/farm/policy.json`, алгоритмы — из `web/farm/workflow-steps.ts` и `web/api/calculate.py`.

## Источники и доказательства

Основная модель Qwen вызывает RouterAI Web Search с Exa: обычно 3 результата, для ключевой темы 5. Текущая политика задаёт ориентир 4 поисковых раунда и **не более 6 оплачиваемых поисковых вызовов**, включая повторы; это ниже цели «до 8» в отчёте v1.3. Нехватка конкретного свидетельства фиксируется как `missingEvidence`. Один раунд сохраняет ответ и annotations (`webRaw:N`), затем отдельный вызов Qwen без web plugin формирует строгий JSON (`webAction:N`). После ошибки структурирования сохранённый поиск может быть использован повторно.

Источник — запись URL и citation-content, возвращённых RouterAI; полного чтения страницы нет. `published_at` остаётся null, если дата отсутствует. Внешним фактом считается лишь claim с sourceId и точной цитатой из сохранённого snippet. Семантическую силу цитаты проверяет агент и независимый критик; точное вхождение строки само по себе не доказывает истинность или полноту контекста. URL без фрагмента не считается достаточным доказательством. Критический этап применяет пороги: 5 подтверждённых источников, 3 организации и 3 альтернативы, плюс пригодный расчёт. При недостатке материалов рекомендация не должна автоматически становиться «Развивать».

## Варианты и исходные данные

Агент предлагает ровно два текстовых варианта одного сценария; возможен вариант с Rules. Dataset содержит два примера по текущей политике, `expected` — проверяемые поля, `baselineSeconds` — время исходного ручного процесса, если оно действительно известно. Если точный пример не подтверждён фрагментом источника, dataset помечается `SIMULATED`. Прогон сохраняет вход, выход, статус, длительность, качество и происхождение. Три повторения одной задачи помогают увидеть нестабильность, но не превращаются в три независимые задачи.

В текущем Workflow ручное время проверки и исправления записывается как null, а baseline из синтетического набора не признаётся измеренным. Поэтому реальный LLM-вызов и измеренное время машины ещё не дают измеренной экономии полного процесса. Это ожидаемый исход многих новых идей: модуль честно возвращает недостаточность данных. Значения `quality` из автоматически созданного expected помечаются синтетическими и не становятся подтверждённой бизнес-метрикой.

## Формула и статистика

Python Function принимает только ID расчёта, выбирает trials/dataset и policy из Neon и сохраняет результат. Для полной сопоставимой пары по одной задаче код требует:

- измеренный baseline в секундах;
- фактическое время вызова (`durationMs / 1000`);
- измеренные секунды ручной проверки и исправления;
- происхождение `MEASURED` для baseline и наблюдения.

Полное время в текущем коде: `durationMs / 1000 + manualReviewSeconds + correctionSeconds`. Разность пары: `baselineSeconds - totalSeconds`; положительное значение означает экономию. Сначала усредняются повторения внутри одной задачи, затем paired bootstrap пересэмплирует задачи. Политика: 10 000 пересэмплирований, seed 42, 95% percentile interval. `n` — число задач с полными парами. При отсутствии таких пар `measuredEffect` равен null. Допуск к положительной рекомендации требует минимум 5 пар, нижнюю границу интервала не менее 1 секунды, измеренное качество не ниже 0,9 и отсутствие ошибок. Эти условия применяет код; LLM не может подменить числа.

Потенциал внедрения считается отдельно от измеренного эффекта. Для сценария с известными baseline, объёмом и машинным временем Python использует формулу `monthlyVolume × volumeMultiplier × qualityMultiplier × (baselineSeconds − machineSeconds − manualRework × baselineSeconds)`. Единица результата — секунд в месяц. Негативный, базовый и благоприятный сценарии, а также чувствительность по объёму, качеству и ручной доработке используют конфигурацию `effect.scenarios`. Если baseline или объём отсутствует, прогноз остаётся null. Сценарное качество/доработка — допущения, даже если машинное время измерено.

## Дополнительные экраны и ограничения

`WhatIfSandbox` в браузере рассчитывает примерную экономику по ползункам ставки, объёма и охвата. В текущем коде при отсутствии измеренной разницы используется **демонстрационное значение 35 сек/операция**, условная цена 0,14 ₽/вызов и другие фиксированные допущения. Эти цифры не поступают из RouterAI usage, не сохраняются в Neon и не должны цитироваться как доказанный ROI.

`PostMvpMonitoring` хранит введённые пилотные наблюдения в `localStorage` текущего браузера. При отсутствии метрик отчёта он использует демонстрационные значения для baseline, качества и цены труда. На основании введённых чисел локально показывает сравнение, но не создаёт Measurement/CalculationRun/Report на сервере, не синхронизирует устройства и не обновляет рекомендацию критика. Такой экран — пользовательский симулятор; проверенный мониторинг A4/A10 остаётся отдельной задачей. Не вводите туда секреты или персональные данные третьих лиц.
