# HTTP API

Все прикладные маршруты начинаются с `/api` и обслуживаются `web/app/api/[...path]/route.ts` → `farmApi`. Динамические ID — UUID. Тела JSON, кроме аудио (`multipart/form-data`); успешный ответ обычно JSON. Код `503` означает недоступность зависимости или нераспознанную внутреннюю ошибку, а не успешное выполнение. `GET /api/public/{token}` — исключение без пользовательской сессии. Детали реализации и схемы полей: `web/farm/api.ts`, `auth.ts`, `contracts.ts`.

## Доступ и общие заголовки

После входа браузер получает `farm_session` (`HttpOnly`, `SameSite=Strict`, в Vercel `Secure`) сроком на 7 дней. В БД хранится только SHA-256 токена. Клиентские мутации требуют `X-Farm-Request: 1`; при наличии `Origin` он должен совпадать с адресом приложения. Сервер проверяет владельца идеи, run, отчёта, файла и MVP. Формы клиента посылаются с `credentials: same-origin`.

Для создания идеи, запуска исследования и вызова MVP нужен `Idempotency-Key` длиной 8–100 символов. Повтор с тем же ключом возвращает ранее созданный объект. Глобальное ограничение мутаций: 100 запросов на пользователя за 10 минут. Дополнительные лимиты есть у входа, аудио и MVP. Публичная ссылка отчёта — bearer capability: любой, кто знает токен, может читать опубликованный отчёт до отзыва ссылки.

## Маршруты

| Метод и путь | Доступ | Действие |
| --- | --- | --- |
| `POST /api/auth/register` | Публично | Создать аккаунт `{username,email,password}`, установить cookie |
| `POST /api/auth/login` | Публично | Войти с `{identifier,password}`, где identifier — логин или почта |
| `GET /api/auth/me` | Сессия | Данные текущего аккаунта |
| `POST /api/auth/logout` | Cookie при наличии | Завершить текущую сессию; без неё операция также возвращает успех |
| `POST /api/audio` | Сессия | Загрузить `file`, сохранить приватно и попытаться распознать; ответ `{artifactId,text,usage,...}` либо `warning` |
| `GET /api/ideas` | Сессия | Список собственных идей |
| `POST /api/ideas` | Сессия + ключ | Создать идею `{title,transcript,priority}`; priority 0/1/2 |
| `GET /api/ideas/{id}` | Владелец | Идея и список runs |
| `PATCH /api/ideas/{id}` | Владелец | Обновить текст/название/приоритет, при содержательной правке создать IdeaVersion |
| `DELETE /api/ideas/{id}` | Владелец | Удалить идею, если нет активной задачи |
| `POST /api/ideas/{id}/audio` | Владелец | Привязать принадлежащий аккаунту `{artifactId}` к идее |
| `POST /api/ideas/{id}/archive` | Владелец | Архивировать идею и отменить активные задания |
| `POST /api/ideas/{id}/start` | Владелец + ключ | Поставить ResearchRun/Job в очередь, ответ 202 |
| `GET /api/ideas/{id}/history` | Владелец | Исторический архив, если он есть; перенос старых данных отключён |
| `GET /api/research/{id}/status` | Владелец run | Статус, progress, последние 80 логов, отчёты и сохранённые шаги |
| `GET /api/research/{id}/execution/{logId}` | Владелец run | Метаданные и вход/выход действия |
| `POST /api/research/{id}/pause` | Владелец run | Пауза на границе шагов |
| `POST /api/research/{id}/resume` | Владелец run | Продолжить сохранённый run |
| `POST /api/research/{id}/retry` | Владелец run | Повторить после ошибки, оставив успешные checkpoints |
| `POST /api/research/{id}/cancel` | Владелец run | Отменить задание |
| `GET /api/reports/{id}` | Владелец run | Полный отчёт |
| `POST /api/reports/{id}/share` | Владелец run | Создать/получить путь публичного отчёта |
| `DELETE /api/reports/{id}/share` | Владелец run | Отозвать публичный токен |
| `POST /api/reports/{id}/decision` | Владелец run | `{action: develop|revise|stop, acceptance?, comment?}`; при develop создаёт MVP Job |
| `GET /api/public/{token}` | Публично | Опубликованный JSON отчёта, `no-store` |
| `GET /api/mvp/{id}` | Владелец идеи | Состояние и MvpSpec |
| `POST /api/mvp/{id}/run` | Владелец + ключ | Проверить поля, вызвать модель/Rules, сохранить результат |
| `GET /api/files/{id}` | Владелец | Поток приватного Blob-объекта |
| `GET /api/microservices/rules/health` | Публично | Состояние Rules |
| `GET /api/microservices/rules/metadata` | Публично | Версия и схема ввода Rules |
| `POST /api/microservices/rules/run` | Внутренний токен | Проверить `{output,fields,requiredValues?}` |
| `POST /api/calculate` | Внутренний токен | Python Function принимает только `{calculationRunId}` и читает входы из Neon |

`/api/calculate` реализован отдельной Python Function, не catch-all Route Handler. Внутренний заголовок `X-Farm-Service` создаётся сервером из `INTERNAL_API_TOKEN`; не передавайте его в браузер. Публичные `health` и `metadata` не доказывают, что LLM, Neon или весь Workflow работают.

## Примеры контрактов

```json
{"title":"Помощник поддержки","transcript":"Нужно ускорить разбор типовых обращений","priority":2}
```

Для `POST /api/ideas` сервер возвращает созданную идею. Далее `POST /api/ideas/{id}/start` без тела возвращает run с `id`, `ideaVersionId`, `status`, `stage`, `config` и счётчиками. При выборе `develop` сервер берёт переданные критерии приёмки либо сохранённые критерии плана, а при их отсутствии — встроенные значения; `override` отмечает несоответствие рекомендации.

Ошибки возвращаются в виде `{"error":"..."}`. Типичные коды: `400` — невалидные поля, `401` — нет сессии, `403` — неподходящее происхождение запроса или внутренний токен, `404` — объект не найден или чужой ID, `409` — конфликт состояния/лимита идей, `413` — большой файл, `429` — ограничение частоты, `503` — зависимость или серверная операция недоступна. Точный текст может меняться; клиенту следует ориентироваться на код и безопасное сообщение.
