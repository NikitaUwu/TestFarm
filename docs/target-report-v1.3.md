1. Краткое резюме изменений 
После версии 1.2 AI-контур был существенно упрощен. Царь Роутер заменен на RouterAI. 
Отдельные сервисы поиска и чтения страниц удалены из обязательного стека. RouterAI теперь 
используется как единая внешняя точка для LLM, STT и веб-поиска. 
Внешний контур после изменений: 
Vercel  → приложение, Workflow, Functions, Blob 
Neon    → PostgreSQL 
RouterAI → LLM, STT, Web Search 
Ключевое следствие: LiteLLM, Tavily, Jina, read_page(), headless browser и отдельный поисковый 
backend не требуются. 
2. Замена Царь Роутера на RouterAI 
Статус: ЗАФИКСИРОВАНО. 
RouterAI становится единым AI-шлюзом проекта. Через него выполняются вызовы языковых 
моделей, распознавание речи и веб-поиск. 
RouterAI 
├── LLM 
├── STT / Whisper 
└── Web Search / Exa 
LiteLLM не используется. Причина: RouterAI уже выполняет функцию модельного шлюза, а 
дополнительный gateway создавал бы лишний слой маршрутизации и эксплуатации. 
Важное изменение относительно прежнего требования бесплатности: RouterAI работает по pay-as-
you-go. Проект остается недорогим, но более не является полностью бесплатным по AI-вызовам и 
веб-поиску. 
3. Зафиксированные модели 
Статус: ЗАФИКСИРОВАНО. 
DEFAULT_LLM = qwen/qwen3.5-9b 
CRITIC_LLM  = openai/gpt-oss-120b 
STT_MODEL   = openai/whisper-large-v3-turbo 
3.1. Qwen3.5-9B — основная рабочая модель 
Используется для большинства этапов фермы: 
 структурирование идеи и формирование карточки; 
 анализ проблемы, аудитории и ограничений; 
 исследовательские этапы с RouterAI Web Search; 
 рынок, конкуренты, тренды и гипотезы; 
 формирование вариантов решения; 
 интерпретация результатов расчетного модуля; 
 подготовка структурированного отчета; 
 генерация MvpSpec для универсального MvpRenderer. 
Причина выбора: более низкая стоимость, поддержка structured outputs, tools/tool_choice и 
достаточный контекст для нашей поэтапной архитектуры. Большой контекст 1M не требуется,

3.2. gpt-oss-120b — независимый критик 
Используется только на критическом этапе. Основная модель проводит исследование, а 
критическая оценка выполняется другой модельной семьей для снижения риска

 выявление blockers и пробелов доказательств;

 итоговая рекомендация. 
3.3. Whisper Large V3 Turbo — STT 
Используется для русского голосового ввода. Аудио хранится в Vercel Blob, а распознавание 
выполняется через RouterAI. 
3.4. Отказ от escalation/fallback-модели 
Статус: ЗАФИКСИРОВАНО. 
Третьей модели для автоматической эскалации нет. Если вызов основной LLM не удался, система 
применяет контролируемые retry по политике Workflow и фиксирует ошибку в ExecutionLog. Скрытая 
замена модели не выполняется. 
4. Веб-поиск через RouterAI 
Статус: ЗАФИКСИРОВАНО. 
Отдельный SearchProvider больше не нужен. Исследовательские вызовы Qwen3.5-9B выполняются 
через RouterAI с подключенным web plugin. Поисковый движок — Exa. 
Research Agent 
    ↓ 
Qwen3.5-9B + RouterAI Web Search 
    ↓ 
Exa 
    ↓ 
research text + url_citation[] 
    ↓ 
Neon 
4.1. Режим поиска 
Для проекта используется явная конфигурация web plugin, а не только суффикс :online. Это дает 
контроль над движком и количеством результатов. 
WEB_SEARCH_ENGINE = exa 
Обычный запрос: max_results = 3 
Ключевая тема: max_results = 5 
4.2. Бюджет поиска 
Поиск ограничивается бюджетом, а не жестким фиксированным количеством шагов: 
 обычный полный прогон: ориентир 4–6 web-search вызовов; 
 верхний предел: около 8 вызовов; 
 дополнительный поиск разрешается, если агент явно фиксирует, какого доказательства ему не 
хватает.

Причина ограничения: веб-поиск, а не токены основной LLM, вероятно будет одной из основных

4.3. Двухшаговый шаблон исследовательского вызова 
Для стабильности данных исследование и строгая структуризация разделяются на два вызова:

Шаг 2: Qwen3.5-9B без Web Search 
→ строгий JSON по схеме этапа 
Это уменьшает риск конфликтов между поиском, citations и обязательным JSON-форматом в одном 
запросе. 
5. Упрощение доказательной базы 
Статус: ЗАФИКСИРОВАНО. 
Отдельное открытие и чтение полной страницы исключено из MVP. Пользователю и отчету 
достаточно сохранять ссылку на источник и те данные, которые реально вернул RouterAI Web 
Search. 
5.1. Что сохраняется в Neon 
EvidenceSource 
- url 
- title 
- publisher/domain, если доступно 
- snippet/content citation, если доступно 
- published_at = null, если дата не получена 
- accessed_at 
- search_topic / search_query 
- supported_claim 
- provider = routerai 
- search_engine = exa 
- raw_citation JSONB 
5.2. Правило доказательности 
Агент не имеет права делать утверждение сильнее, чем поддерживает полученная citation. Если 
данных недостаточно, он должен выполнить дополнительный поиск либо явно зафиксировать 
«Недостаточно данных». Неизвестная дата публикации не угадывается и сохраняется как null. 
Компромисс осознанный: система не перечитывает полный документ и поэтому может не видеть 
весь контекст источника. Для тестового проекта это принято ради простоты. При необходимости 
read_page() можно добавить позднее без изменения общей архитектуры. 
6. Компоненты, исключенные из обязательного стека 
После изменений из обязательного runtime-контура удалены: 
 Царь Роутер; 
 LiteLLM; 
 Tavily; 
 Jina Reader/Search; 
 собственный read_page(url); 
 HTML parser / Readability для исследований; 
 headless browser / Playwright для чтения источников; 
 отдельная escalation/fallback LLM.

8. Что осталось без изменений 
Следующие решения из версии 1.2 сохраняются: 
 приоритетная очередь в Neon: HIGH / MEDIUM / LOW + FIFO + aging; 
 Dispatcher выбирает следующую задачу, одновременно выполняется один тяжелый Research 
Workflow; 
 Vercel Queue не используется; 
 расчетный модуль — Python Function + NumPy/SciPy; 
 измеренный эффект отделен от потенциального; используются paired bootstrap, 95% CI, три 
сценария и sensitivity analysis; 
 MVP создается как MvpSpec + универсальный MvpRenderer; 
 Rules & Validation Service остается отдельно вызываемым компонентом внутри одного Vercel-
проекта; 
 ExecutionLog хранит действия agent / tool / system; 
 UI обновляет прогресс через polling, WebSocket/SSE не обязательны; 
 отдельные роли пользователей и сложная авторизация не используются. 
9. Текущие неопределенности и риски 
 RouterAI — платный сервис. Необходимо установить лимиты расходов на один research run и 
мониторить фактическую стоимость. 
 Цены RouterAI и Exa могут меняться; лимиты и бюджеты должны храниться в конфигурации, а 
не быть жестко зашиты в код. 
 Qwen3.5-9B требуется проверить на реальных русскоязычных сценариях: JSON Schema, 
последовательные tool/search вызовы, качество аналитического текста. 
 Search citation не является полной копией страницы. Это принятый компромисс MVP; сильные 
выводы должны соответствовать реально полученному фрагменту. 
 Дата публикации источника может отсутствовать. В таком случае система показывает 
отсутствие данных, а не пытается восстановить дату догадкой.
