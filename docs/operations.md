# Эксплуатация и восстановление

Текущий контур — Vercel + Neon + Private Blob + RouterAI. Руководство первичного запуска: [развёртывание](serverless-deployment.md). В этом документе описано, где искать сбой и какие данные сохраняются. Действия с реальными секретами, платными вызовами и рабочими данными выполняйте только в рамках отдельного согласованного операционного запроса.

## Наблюдение за задачей

Страница опрашивает `/api/research/{id}/status` примерно каждые 3 секунды. Ответ содержит `status`, `stage`, `progress`, `warnings`, `counters`, до 80 последних записей ExecutionLog, отчёты и результаты шагов. Если этап выглядит зависшим, сопоставьте Job `status`, `workflowId`, `startingAt`, run status и последнее действие. Чтение статуса запускает `reconcileDispatcher` после ответа. Технические Vercel logs дополняют, но не заменяют Neon ExecutionLog.

| Симптом | Что проверить | Ожидаемое действие |
| --- | --- | --- |
| Регистрация/вход недоступны | `NEON_BASE`/`DATABASE_URL`, миграция, время ответа Neon | Восстановить соединение/схему; не сбрасывать БД ради входа |
| Очередь не движется | Job `queued/starting/running`, advisory lock, запускающийся Workflow | Проверить dispatch/reconcile; `starting` старше политики возвращается в очередь |
| Шаг RouterAI завершился ошибкой | ExecutionLog: модель, статус, usage, retries и сообщение; серверная переменная | Исправить конфигурацию/доступ; повторить run, если ещё есть бюджет |
| Источников мало | webRaw/webAction, citations и `missingEvidence`, лимиты поиска | Оставить пробел в отчёте; изменение политики — новая версия и новый run |
| Python расчёт недоступен | `INTERNAL_API_TOKEN`, APP_ORIGIN, лог Function, CalculationRun ID | Восстановить внутренний вызов; не подставлять произвольные числа |
| MVP не завершается | Job kind `mvp`, результат шага, статус Rules, бюджет `mvpSpend` | Продолжить/повторить с сохранённым run по правилам workflow |
| В отчёте нет измеренного эффекта | Наличие полных пар MEASURED baseline/review/correction и measured quality | Собрать действительные измерения; нулём пропуски не заменять |

Пауза, отмена и архивирование прекращают дальнейшие шаги; уже отправленный платный запрос может завершиться. Состояние `failed` требует видимой ошибки; результат отдельного этапа может быть сохранён как `unavailable` с предупреждением. Это не равно доказанному успеху интеграции.

## Расходы и лимиты

`policy.json` задаёт предел 20 ₽ на исследование и 5 ₽ для операций MVP, резервы 1 ₽ на основной LLM, 2 ₽ на критика и 2/3 ₽ на обычный/ключевой поиск. `paidCall` в транзакции блокирует новые вызовы, если сумма подтверждённой стоимости, удержанных резервов и новой оценки превышает предел. После ответа `usage.cost` переводит резерв в подтверждённые расходы. При сетевой неопределённости или отсутствии цены резерв удерживается, а warning записывается. Это ограничение новых вызовов; окончательная цена уже отправленного запроса контролируется RouterAI. STT до создания ResearchRun учитывается отдельно в log, без этого 20-рублёвого лимита.

Изменение ставок резерва, списка моделей, таймаутов, числа поисков или порогов требует новой версии политики; существующий run хранит прежний snapshot. Текущий `targetCalls=4`, `searchCalls=6`, `llmCalls=40`, `trialCases=2`, `trialRepetitions=3`, `retries=2`, `researchMinutes=30`. Не обещайте фиксированный тариф Exa/RouterAI по этим числам.

## Резервное копирование и восстановление

Бизнес-данные и журнал находятся в Neon; файлы — в Private Blob. Для согласованного восстановления нужны оба набора с сохранением связей `farm_artifacts.pathname` ↔ Blob object. У текущего проекта нет автоматизированной процедуры резервного копирования/restore drill для этого контура. Перед массовой миграцией или удалением настройте средства Neon/Vercel, получите отдельную копию и проверьте восстановление в отдельном окружении. Не запускайте старые Docker-скрипты восстановления: они относились к удалённому backend и MinIO.

Миграции Drizzle находятся в `web/drizzle`; `web/scripts/migrate.ts` читает локальное окружение и применяет их. Применённый SQL не переписывайте; следующую схему оформляйте новой миграцией. Для предварительной проверки изменённых исходников на отдельном окружении доступна команда `pnpm typecheck` и `pnpm build`, но в текущем запросе эти проверки не запускались. Публикация документации на GitHub не равна новой публикации Vercel.

## Версии и изменения

При изменении требования сверяйте [реестр](requirements.md), модель данных, API, документы хранения и журнал `development-log.md`. Если новое наблюдение должно изменить расчёт или рекомендацию, текущий клиентский пилотный экран недостаточен: потребуется серверная версия Measurement/CalculationRun/Report и связанная миграция. Секреты никогда не записываются в документы и Git.
