# Политика данных

Версия: 2, локальный прототип, 2026-09-09.

PostgreSQL хранит логины, почту, солёные scrypt-хеши паролей, сессии, карточки/версии, dataset JSON, источники, ответы шагов, реальные входы/выходы, измерения, расчёты, отчёты, решения и MVP. Данные входа не отправляются ИИ-провайдерам. Почта используется как идентификатор входа; подтверждение владения почтой и почтовое восстановление пароля не реализованы. Аккаунт сохраняется при удалении идеи; самостоятельного удаления аккаунта пока нет. MinIO хранит исходное аудио и исходную расшифровку как отдельные артефакты. Исправленный текст записывается в новую IdeaVersion. История не переписывается.

Данные сохраняются до удаления идеи владельцем; автоматического TTL идей нет. Сессии действуют 12 часов. Резервные копии управляются оператором, рекомендуемый локальный срок — 7 дней; очистка копий не автоматизирована. Не загружайте данные третьих лиц без необходимого основания.

ИИ-провайдер получает только данные конкретного вызова, перечисленные в [интеграциях](integrations.md). Секреты лежат server-side в `.env`, исключены из Git и Docker build contexts. Отчёт не включает ключи. Локальное удаление не меняет политики внешнего поставщика.

Текущий получатель — Groq Cloud: содержание карточки, выдержки из источников, вход отдельного эксперимента либо аудио конкретного STT-вызова. Для планирования поиска передаются название, проблема, аудитория и исходный transcript как запасной контекст; web_search получает полученный короткий английский запрос; для генерации MVP — идея, критерии приёмки и ошибки валидации; при работе MVP — поля формы. Встроенный web_search выполняется инфраструктурой Groq и её поисковой интеграцией. GrokKey.txt и прежний openrouter.txt исключены из Git; build contexts ограничены backend/ и web/. Groq по умолчанию не сохраняет содержание inference, но допускает временные журналы ошибок и злоупотреблений до 30 дней; метаданные использования сохраняются. ZDR определяется настройками аккаунта и агентом не включался. См. [политику Groq](https://console.groq.com/docs/your-data). Ранее отправленные данные OpenAI/OpenRouter остаются под политиками тех сервисов.

Каждый зарегистрированный аккаунт имеет отдельный principal. Каждый объект проверяется сервером по owner_id, включая аудио, dataset, run, report и MVP. Публичная ссылка создаётся явным действием пользователя; доступна проекция отчёта без исходного аудио и dataset. Получатель ссылки может сохранить копию; локальное удаление не удаляет такую копию.

Удаление идеи: сначала отклоняется при активном выполнении, затем удаляются бизнес-данные и checkpoints, ключи объектов и префиксы запросов Runner передаются в deletion_jobs. Worker удаляет S3-объекты и сохранённые результаты SQLite Runner через /purge; при ошибке задание сохраняет ошибку и повторяется. Удаление считается завершённым после completed в deletion_jobs. Архивирование не удаляет данные. Копии в .local/qa/restore-* содержат данные на момент snapshot и подчиняются отдельному сроку хранения резервных копий.

Логи содержат типы ошибок и безопасные сообщения, не provider response body. Prompt injection ограничивается разделением инструкций и недоверенных входов; модель не получает произвольного исполнения команд. Ограничения Runner описаны в [архитектуре](architecture.md).
